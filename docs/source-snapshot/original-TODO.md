# قائمة تجهيز نقل منصة البرازيلي

> حُفظ سجل المنتج والتفاصيل التاريخية الوارد مع المصدر في `TODO_IMPORTED_SOURCE.md`. هذه القائمة تتبع أعمال الاستيراد والتشغيل في مشروع Manus الجديد فقط.

## 1. استيراد المصدر وحماية المواد الحساسة — مكتمل
- استيراد مشروع React/Express/tRPC/Drizzle كاملاً إلى مشروع «البرازيلي» المُدار، مع واجهات اللاعب وصاحب الملعب والإدارة، وصفحة التحميل، ومشروع Android المرفق.
- الحفاظ على Git وتعريف مشروع Manus الجديد بدلاً من نقل هوية المشروع القديم أو أسراره.
- نقل مفتاح توقيع Android إلى مخزن محلي خاص خارج شجرة المصدر؛ لا يُنسخ إلى Git أو ملفات الويب أو متغيرات العميل.
- حفظ قائمة المهام الأصلية وسجل حالة المزايا كما وردا من المصدر في ملف مستقل دون الادعاء بنقل بيانات المستخدمين أو الإنتاج.

## 2. تشغيل الخادم والواجهة وربط الموارد المُدارة — مكتمل
- استخدام خادم Webdev وقاعدة MySQL مُدارة للمشروع الجديد؛ لا تُنقل قاعدة بيانات أو تخزين أو نطاق أو نشر المشروع القديم.
- تثبيت الاعتماديات المقفلة بواسطة `pnpm@10.18.0` مع الاحتفاظ بسياسة حزم البناء الموجودة في `pnpm-workspace.yaml`.
- تطبيق ترحيلات Drizzle المرفقة بعد التحقق من أنها لا تتضمن عمليات حذف أو إسقاط؛ تظل بيانات البيئة الجديدة منفصلة عن المصدر القديم.
- إبقاء المسارات المعلنة في `client/public/manus-routes.json` متسقة مع الواجهة المستوردة، وتشغيل خادم Express على المنفذ المُدار.

## 3. مفاتيح البيئة والمصادقة — مكتمل
- قيم Manus المُدارة للمشروع (`DATABASE_URL`، مفاتيح الخدمة، وإعدادات OAuth/JWT) تأتي من المنصة ولا تُكتب يدوياً أو تُستبدل.
- إدخال إعدادات البريد في نموذج مفاتيح محمي فقط: `SMTP_HOST` و`SMTP_PORT` و`SMTP_USER` و`SMTP_PASSWORD` و`SMTP_FROM`.
- إدخال `ADMIN_EMAIL` في نموذج محمي لتعيين صاحب حساب الإدارة الأول وتلقي تنبيهات التسجيل؛ لا تُطبع القيم أو تُحفظ في المصدر أو السجل.
- تفعيل التسجيل وتسجيل الدخول واستعادة كلمة المرور من خلال البريد وجلسات التطبيق بعد استكمال المفاتيح وإعادة تشغيل الخدمة.

## 4. التحقق قبل التسليم — مكتمل
- تشغيل `pnpm check` و`pnpm test` و`pnpm build` بعد مزامنة الاعتماديات والترحيلات.
- التحقق من `/api/health` و`/manus-routes.json` على خادم التشغيل، مع فحص تشخيص TypeScript الآلي.
- عدم إرسال رسالة اختبار إلى عميل حقيقي أو إنشاء مستخدم/حجز إنتاجي؛ يجيز طلب البريد الحالي معاينة stream transport والتحقق من اتصال SMTP والبيانات المقروءة فقط.

## 5. إصدار Android لاحقاً — جاهزية فقط
- يبقى التطبيق Android غلاف WebView للتطبيق المنشور؛ يلزم تحديث `server.url` في `android-wrapper/capacitor.config.ts` قبل بناء نسخة مرتبطة بنطاق النشر الجديد.
- لا يُبنى APK جديد أو يُرفع قبل تأكيد عنوان النشر وزيادة رقم الإصدار؛ يظل مفتاح التوقيع خارج المصدر.


# توسعة الشبكة الاجتماعية والمحادثات والتوزيع — 2026-10-25

## 6. ملفات اللاعبين والصداقة والبحث — مكتمل
- يتيح ملف اللاعب إدخال وتعديل الاسم والعمر ومركز اللعب والصورة الشخصية الاختيارية، مع خانة اختيارية للسيرة الذاتية (Bio).
- يتضمن التطبيق اقتراح لاعبين وإرسال واستقبال طلبات صداقة/متابعة، وتظهر المحادثة الثنائية بين لاعبين فقط بعد موافقة الطرفين المتبادلة.
- يتيح البحث عن اللاعبين بالاسم وتصفية النتائج حسب مركز اللعب؛ لا يُكشف البريد الإلكتروني أو الهاتف في دليل اللاعبين.
- يظل حساب الدخول والبريد المُوثق صالحين كما هما؛ حقول الملف الرياضي لا تستبدل اعتماد تسجيل الدخول.

## 7. المحادثات المتقدمة — مكتمل
- تدعم المحادثة الرسائل النصية والرسائل الصوتية، وحذف الرسالة لدى المستخدم وحده أو حذفها للجميع وفق صلاحية المرسل.
- تعرض المحادثة حالة الاتصال («متصل الآن» أو «آخر ظهور») وإيصالات القراءة. تُظهر للمُرسل علامتي صح زرقاوين على رسائله بعد ظهور الرسالة الواردة للطرف المقابل داخل مساحة المحادثة؛ لا تكشف للعملاء أسماء القارئين، وتبقى تفاصيل القراءة بالاسم للإدارة ضمن شاشة المراجعة المصرح بها.
- يظهر شات الإدارة والدعم تلقائياً في أعلى قائمة المحادثات، ولا يمكن للمستخدم حذفه أو حظر الإدارة من هذه المحادثة؛ تظل إدارة ومراجعة المحادثات في لوحة الإدارة محكومة بصلاحياتها.
- عند انضمام اللاعب إلى حجز أو مباراة/فريق، يُضاف تلقائياً إلى غرفة المجموعة المرتبطة به؛ ويُضاف منشئ المباراة وأعضاؤها إلى شات المباراة تلقائياً.
- تبقى غرف المباريات والحجوزات والمحادثة الثنائية ومحادثة الدعم منفصلة السياق، وتُطبق صلاحية العضوية على قراءة وإرسال الرسائل.

## 8. أداء واستقرار الواجهة — مكتمل
- تضبط سياسة تخزين مؤقت سريعة للبيانات العامة مع تحديث البيانات المتغيرة مثل الجلسة والحجز والمحادثة دون خلط حالة المستخدم المسجل بحالة الزائر.
- لا تُجلب بيانات غير لازمة للمسار المفتوح؛ ويُحدّث الشات والحضور على نحو نشط أثناء المشاهدة فقط، مع إبطال cache بعد التغييرات.
- تبقى واجهات الهاتف قابلة للاستخدام باللمس وبلا جلب متكرر غير محدود أو نمو غير محدود لقوائم الرسائل.
- لا يُوعد بغياب مطلق لأي تأخير/لاج؛ تُوثق نتائج الفحوص ومصادر الضغط المتبقية.

## 9. تحديث Android وتنزيل Windows — مكتمل مع تنبيه إعادة التثبيت للإصدارات القديمة
- [x] تحتوي صفحة التنزيل بجوار زر «تثبيت التطبيق» على إجراء «تنزيل التحديثات تلقائياً» يفحص الإصدار الحالي ويبدأ تنزيل أحدث APK رسمي عند توفره.
- [x] يظل تثبيت APK خارج Play Store خاضعاً لتأكيد نظام Android وصلاحية مصدر التثبيت؛ لا يجري تثبيت صامت على جهاز المستخدم.
- [x] تتوفر نسخة Windows Desktop مخصصة للتطبيق عبر مُثبّت قابل للبناء والتوزيع، ويُدار إصدارها ومصدر تنزيلها من لوحة الإدارة؛ أُنتج مُثبّت 1.0.2 ورُفع إلى CDN عام.
- [x] لا تُربط الحزم بعناوين Preview أو نطاق قديم؛ نُشر الموقع على `https://elbarzily-tsfy8328.manus.space`. وافق المستخدم على إنشاء مفتاح توقيع Android جديد بعد نسيان كلمة مرور المفتاح السابق؛ يلزم إزالة النسخة المثبتة بالمفتاح القديم قبل تثبيت APK الجديد، وتظل بيانات الحسابات على الخادم.
- [x] رُفع APK موقّع 1.0.2 إلى CDN وأُدرج رابط Android بجانب مُثبّت Windows في إعدادات صفحة التنزيل؛ تستخدم الإصدارات القادمة مفتاح v2 نفسه.

## 10. مخطط البيانات وواجهات API الآمنة — مكتمل
- تكون تغييرات MySQL إضافية ومتوافقة مع الرسائل والحسابات والحجوزات القائمة؛ لا تُحذف بيانات قديمة.
- تُتحقق ملكية مرفقات الصوت والصلاحيات وموافقة الطرفين في الخادم لا في الواجهة فقط.
- لا تتضمن استجابات دليل اللاعبين أو محادثات المستخدم بيانات كلمات المرور أو مفاتيح البيئة أو بيانات اتصال غير لازمة.

# تطوير نظام البريد الإلكتروني الرياضي — 2026-10-28

## 13. هوية موحدة وقوالب Gmail متجاوبة
- لكل الرسائل قالب HTML مشترك احترافي بألوان كحلي داكن وأسود وأخضر رياضي، مع شعار البرازيلي في الأعلى واسم «تطبيق البرازيلي ⚽»، وخلفية أنيقة وبطاقات داخلية مرتبة وأزرار خضراء واضحة.
- يدعم القالب الهاتف والكمبيوتر وGmail، واللغة العربية واتجاه RTL وخطاً واضحاً ومسافات مريحة، ويضيف إلى كل رسالة التذييل الثابت «البرازيلي — ملعبك، فريقك، ماتشك ⚽».
- يوجد قالب منفصل منظم لكل نوع رسالة مع الحفاظ على الهوية البصرية؛ لكل رسالة نسخة نصية بديلة، وتُهرب القيم الديناميكية قبل إدخالها إلى HTML.

## 14. التحقق والترحيب
- تتضمن رسالة OTP اسم العميل إن توفر، والكود كبيراً وواضحاً، ووقت انتهاء الصلاحية الفعلي، ورابط التحقق فقط إن كان النظام يدعمه، وتنبيهاً بعدم مشاركة الكود؛ لا تُختلق روابط لأن التدفق الحالي يعتمد إدخال الرمز.
- تتضمن رسالة الترحيب اسم العميل، وتاريخ إنشاء الحساب من السجل الحقيقي، وزراً يفتح التطبيق على النطاق المنشور.
- يُنشأ الحساب بنجاح وتُعتمد صحة OTP قبل إرسال الترحيب؛ لا تُكشف كلمة المرور أو OTP أو بيانات SMTP في متصفح أو سجل.

## 15. تأكيد الحجز وتذكيره
- لا تُرسل رسالة الحجز إلا بعد نجاح حفظ الحجز ومعاملة قاعدة البيانات؛ وتعرض الاسم ورقم الحجز والملعب والعنوان وتاريخ الموعد ووقت البداية والنهاية والسعر الإجمالي والحالة وحالة الدفع وزراً يفتح تفاصيل الحجز الفعلية.
- تعرض القيم وفق السجل الحقيقي وحالة الحجز؛ لا توصف طلبات الحالة `pending` بأنها مؤكدة، ولا يوصف الإيصال المرفق كتحصيل مالي مؤكد.
- ترسل رسالة تذكير للحجز المقبول تتضمن الاسم والملعب وعنوانه والموعد والوقت المتبقي ورقم الحجز وزر تفاصيله، مع منع تكرار التذكير لنفس الحجز.

## 16. تحديث الحجز وإلغاؤه
- تعرض رسالة تحديث/رفض/إلغاء اسم العميل ورقم الحجز والحالة الجديدة وسبب التغيير إن توفر؛ تعرض الموعد القديم والجديد فقط عندما تكون بيانات تغيير الموعد موجودة فعلياً.
- يمكن للاعب إلغاء حجزه المستقبلي المسموح به فقط بعد تحقق الخادم من ملكية الحجز وحالته؛ لا يمكنه إلغاء حجز لاعب آخر أو موعد ماضٍ.
- يتضمن إشعار الإلغاء حالة الاسترداد إذا وُجدت قيمة مسجلة في النظام؛ لا توجد حالياً حقول استرداد مستقلة، لذلك لا يُدّعى رد المبلغ أو تُختلق حالة استرداد.

## 17. SMTP، المصدر الحقيقي، والتكامل والاختبار
- تمر الرسائل عبر Nodemailer وإعدادات Gmail/SMTP الحالية المحمية؛ اسم العرض هو «تطبيق البرازيلي ⚽»، ولا تُكتب الأسرار أو OTP في الشيفرة أو قاعدة البيانات أو السجلات.
- تُربط الرسائل بحقوق المخطط الفعلية `users` و`auth_otps` و`bookings` و`pitches` و`pitch_fields` و`schedules`؛ يُستخدم توقيت `Africa/Cairo` وعملة الجنيه المصري «ج.م» كما في التطبيق، ولا تُعرض قيم فارغة أو تجريبية في الرسائل الفعلية.
- تُختبر جميع الأنواع على القوالب ونسخة HTML/plain-text وescaping وروابط CTA عبر اختبارات المشروع ومعاينة stream transport، وتُعاين بيانات حجز موجودة للقراءة فقط، ويُتحقق من اتصال SMTP الفعلي دون إرسال رسائل إلى عملاء حقيقيين أو تعديل حجوزات إنتاجية. عند الفحص أعادت قاعدة البيانات المشتركة 0 حجوزات؛ لذلك تعذرت معاينة حجز فعلي ولم تُنشأ سجلات اختبار في قاعدة الإنتاج المشتركة، واستُخدمت fixtures في اختبارات القوالب.
- يُشغّل callback التذكير عبر Heartbeat مصادق عليه مرة كل 5 دقائق؛ لا تُقبل طلبات HTTP مجهولة لتشغيل الإرسال.


# فتح الروابط داخل التطبيق وإصلاح الميكروفون — 2026-10-29

## 18. فتح روابط البريد في التطبيق أو الويب
- تستخدم أزرار الترحيب روابط الحجز والتذكير وتحديث/إلغاء الحجز وإشعار الإدارة روابط HTTPS ثابتة على نطاق الإنتاج؛ عند فتحها على Android verified App Links توجّه إلى المسار المقابل داخل التطبيق المثبّت، وعند عدم تثبيته أو عدم التحقق تظل صالحة على الويب.
- تدعم المسارات المحددة `/open` و`/open/admin` و`/open/booking/{id}` فقط؛ بعد المصادقة يفتح المستخدم الصفحة المقصودة، ويحافظ رابط الحجز على معرّفه. لا تُقبل عناوين أو وجهات تحويل أو معاملات arbitrary من الرابط.
- يسجل Android النطاق الدائم مع `autoVerify` وDigital Asset Links المطابقة لـ`com.elbarzily.app` وبصمة شهادة الإصدار الحالية، ويعالج الرابط في التشغيل البارد والحار من دون فقد مسار الحجز.
- يسجل Windows بروتوكول `elbarzily://` للمسارات المحلية نفسها، ويفتح نسخة واحدة موجودة عند الضغط أثناء تشغيل التطبيق؛ إذا لم يكن Windows app مثبتاً يعود رابط HTTPS إلى نسخة الويب الحالية.
> استكمال هذه الدفعة: عولج التشغيل البارد في `MainActivity` بقراءة `Intent` داخل `onCreate`، مع الإبقاء على معالجة `onNewIntent` للتشغيل الحار؛ تحققت اختبارات روابط Windows وفحوص الويب والبناء.

## 19. إذن تسجيل الصوت على الهاتف وWindows
- يعلن Android إذن `RECORD_AUDIO` و`MODIFY_AUDIO_SETTINGS` ويستدعي Capacitor مطالبة نظام Android عند بدء المستخدم تسجيل رسالة صوتية فقط؛ لا يُطلب الإذن عند فتح التطبيق.
- على Windows يُسمح بطلب صوتي فقط من أصل الإنتاج الموثوق؛ لا يُمنح إذن الكاميرا أو مشاركة الشاشة عبر معالج صلاحيات الصوت.
- عند رفض الإذن أو غياب الميكروفون أو انشغاله تظهر رسالة عربية تميّز السبب وتعطي الإجراء المناسب؛ لا يُعرض نص استثناء المتصفح الخام للمستخدم.

## 20. الاحتفاظ بتسجيل الدخول في Windows
- يستخدم التطبيق `session.defaultSession` نفسها الموجودة حالياً، وبنفس هوية التطبيق ومجلد بيانات المستخدم، من دون إنشاء partition جديد أو مسح cookies/local storage.
- تُحفظ بيانات الجلسة عند الإغلاق الطبيعي، وتظل إعدادات حذف بيانات المستخدم عند إزالة المُثبّت معطّلة حتى لا تضيع الجلسات أثناء التحديث.
- يفتح كل تحديث المُثبّت فوق النسخة الموجودة ويحافظ على هوية التطبيق؛ لا يُجبر المستخدم على تسجيل خروج عند فتح رابط بريد أو تشغيل نسخة أحدث.
